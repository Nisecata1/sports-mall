# 运动装备商城项目总结报告

软件0.3.3，2026-11-09。总结覆盖当前课程项目的实现、运行与核对过程。

## 1. 项目形成过程

项目从MySQL分类、商品表和Java商品查询开始，随后建立用户、订单、档案及价格快照，接入MongoDB详情、评论与日志，逐步增加浏览统计和管理功能。桌面窗口与HTTP后端分进程运行后，界面输入、请求路由、业务规则、DAO和数据库有了明确的职责对应。

开发采用AI辅助实现，学习过程包含需求选择、逐步运行、GUI操作、SQL和Mongo查询核对，以及对实际文件与调用链的追问。用户确认过商品单价与订单金额规则，持续反馈运行错误和界面结果。自动工具承担构建、隔离实库检查、演示数据与性能测量，报告分别注明这些来源。

## 2. 完成内容

当前形成六张MySQL表、四个Mongo集合、两个视图、两个存储过程、两个订单触发器和三条聚合管道。业务覆盖账号、档案、分类、商品、订单、评论、浏览统计和日志导入。演示数据配额经过主库回执和用户截图核对。

日志导入将原文中的Mongo日志与JDBC批处理要求衔接起来。MySQL先保存暂存行，Mongo按稳定编号同步，再确认SQL状态，失败后通过重试收敛。商品和订单查询索引通过原SQL的结果对照及执行计划测量。

## 3. 对数据库与工程的理解

建模需要明确一条记录代表什么、记录之间怎样关联，以及哪些限制应由数据库维护。商品表的category_id引用分类记录，profiles.user_id的唯一约束表达每个用户至多一份档案。订单金额作为历史快照保存，商品改价后的订单仍有可解释的成交依据。

事务边界在下单和档案等真实操作中落实，Java组织一组SQL修改，失败时处理该事务的结果。跨MySQL与MongoDB的导入则需要保存中间状态和稳定编号。索引的选择结合真实筛选与排序，再观察读取行数和返回结果。

前端窗口提供输入与展示，后端执行身份、业务校验和DAO调用，数据库负责保存及执行约束。构建生成JAR，启动脚本加载对应版本，运行进程、磁盘源码与数据库对象各有自己的更新时点。这些区别通过实际操作逐步形成认识。
