# 运动装备商城用户手册

软件0.3.3，2026-11-09。操作环境为Windows PowerShell 7、JDK17以上、MySQL8以上与MongoDB5以上。

## 1. 启动项目

1. 双击C:/develop/MySQL/启动MySQL.cmd，等待数据库就绪。它启动保存账号、商品和订单的MySQL进程。
2. 双击C:/develop/MongoDB/启动MongoDB.cmd，等待数据库就绪。它启动保存详情、评论和日志的MongoDB进程。
3. 在sports-mall目录双击Start-Backend.cmd，按本地提示输入MySQL连接密码。后端创建连接池、MongoClient和HTTP服务，等待商城窗口请求。
4. 双击Start-Mall.vbs，打开商城窗口。输入已经注册的商城账号和商城密码，点击登录。

后端终端显示http://127.0.0.1:18808时可以登录。结束使用时先退出商城，再在后端及数据库窗口结束相应进程。重新构建后，通过启动脚本加载新版JAR。运行中的进程继续使用它启动时加载的代码。

## 2. 普通用户操作

### 2.1 注册与登录

在登录页选择注册，填写用户名、邮箱、可选电话和两次密码，确认保存。注册产生USER账号。界面将数据提交到后端，后端校验后在MySQL写入密码哈希。用户名或邮箱冲突会显示业务提示。成功登录后，后端建立会话并向MongoDB记录登录结果。

### 2.2 商品浏览与下单

点击商品浏览。名称关键词、直接分类、价格范围共同生效，选择排序后点击查询，使用上一页与下一页切换。分类精确匹配直接所属分类。默认每页10条。

选择商品后打开详情，窗口会显示MySQL中的名称、价格、分类和MongoDB中的说明、语言、图片地址。关闭本次详情浏览后，后端记录VIEW和停留时长。

选择购买并核对当前金额，确认下单。前端将商品编号与确认价交给后端，后端在MySQL事务中重新取价并保存订单。成功后显示订单编号，状态为待处理。价格已经变化时，按提示重新查询并确认。

### 2.3 我的订单

点击我的订单，按当前状态、开始日期和结束日期筛选。日期包含填写的首尾日。选中待处理订单后点击取消并确认。订单按当前状态显示，创建时间和成交金额继续保留。

### 2.4 商品评论

在商品评论页选择商品，填写1至5分、文字和可选标签。标签用逗号分隔，最多5个。确认后，后端写入MongoDB并显示保存结果。

查看我的评论可编辑本人文字、评分、标签，或在确认后删除。最新评论以时间和编号倒序显示。管理员审核入口提供查看与删除。

### 2.5 我的账号与档案

点击我的账号查看账号、联系方式、档案和订单概览。修改电话后保存。点击编辑我的档案可填写姓名、证件、地址和备注，首次保存新增档案，后续保存更新同一份。删除我的档案需确认。

该操作经过前端表单、PUT /api/me/profile、ProfileService、ProfileDao，最后更新profiles。资料与订单概览读取两个MySQL视图，便于对照数据库结果。

### 2.6 数据统计

近7天热门排行显示浏览次数、累计停留和商品名称。我的近7天活动显示本人浏览、去重商品、累计时长、活跃日期和最近浏览时间。商品评论统计显示条数、均分和评分分布。我的月度订单按订单创建月份和查询时的当前状态统计，金额累计该月创建且当前已完成的订单金额。

## 3. 管理员操作

| 页面 | 操作步骤与结果 |
| --- | --- |
| 用户管理 | 刷新列表，选中账号，修改角色或启停并确认，后端重新检查管理员权限 |
| 分类管理 | 选择节点后新增子分类、编辑名称与上级、删除空分类，保存后刷新树 |
| 商品管理 | 新增或编辑名称、直接分类、正数价格及上下架状态，保存后读取MySQL结果 |
| 商品详情 | 选择商品后独立维护说明、图片地址和语言，保存到MongoDB |
| 订单管理 | 按用户、状态、日期查询，选择待处理订单并完成或取消 |
| 评论管理 | 查看最新记录，选择评论并确认删除 |
| 系统日志 | 按用户、类型、等级和日期查询，选择记录查看详情或导入JSONL |

分类移动需保持树结构，存在子分类或商品引用时按提示处理。商品上下架影响后续浏览和下单，已保存订单保留成交信息。用户角色和状态变更会影响后续受保护操作。

## 4. 日志导入

在系统日志页点击导入JSONL日志，选择UTF-8文件并确认。示例位于docs/演示数据/日志导入示例.jsonl。每行使用user_id、timestamp、level、message、operation字段，user_id可以为空，时间采用ISO格式。

导入回执显示批次、暂存、已确认同步和待同步数量。待同步大于0时，保留原文件，在连接恢复后由同一管理员重新导入。后端先提交MySQL暂存，再同步MongoDB，稳定编号使已成功记录可以继续确认。

单批最多200条，文件最多64KiB。导入结果标记为IMPORT。查看详情可以区分日志主体、导入操作者与操作来源。

## 5. DbGate查看数据

MySQL连接使用127.0.0.1、18306、配置中的数据库用户与连接密码，默认库sports_mall。MongoDB连接使用mongodb://127.0.0.1:27017，选择sports_mall。在对应连接中新建查询后执行SQL或Mongo查询。

已打开的查询页保留创建时绑定的连接。执行Mongo语句前检查当前查询属于MongoDB。DbGate查询直接使用db.comments.find等表达式，mongosh的use辅助命令用于终端环境。

用户提供的六表数量截图与主库回执一致。演示数据标有课程演示，适合观察分页、筛选、树关系和聚合变化。Prepare-CourseData.cmd负责准备和核对数据，常规执行由助手完成。首次准备后按普通启动步骤使用即可。

## 6. 从空数据库复现

本节适用于新的本机实例。当前课程实例已经保存业务数据，日常使用按第一节启动。

1. 建立并启动MySQL和MongoDB实例，配置端口与application.properties。本机路径不同的机器需要调整启动脚本和测试运行器路径。
2. 在MySQL管理工具依次执行mysql_schema.sql、mysql_log_import.sql、mysql_views.sql、mysql_procedures.sql、mysql_triggers.sql。脚本位于src/main/resources/sql。
3. 使用mongosh执行mongodb_init.js、mongodb_comment_indexes.js、mongodb_log_indexes.js，建立集合和索引。此时详情集合等待实际商品编号。
4. 在工程目录运行mvnw.cmd package，启动后端与窗口，注册一个自己设置密码的商城账号。以下示例使用用户名mall_admin01。
5. 数据库操作者在DbGate核对刚注册账号，将它设为ADMIN，随后重新登录。用户名采用其他值时，先替换下面两处用户名再执行。

```sql
SELECT user_id, username, role FROM sports_mall.users WHERE username='mall_admin01';
UPDATE sports_mall.users SET role='ADMIN'
WHERE username='mall_admin01' AND role='USER' AND status=1;
```

6. 双击Prepare-CourseData.cmd，在本地输入数据库连接密码。它使用已有有效管理员处理日志导入，添加带标记的演示数据，并建立两个MySQL查询索引。工具重复执行后给出配额和保留情况。
7. 回到商城窗口查看商品、评论、统计和管理员页面。新实例会得到自己的自增编号，跨库文档随这些实际编号关联。

## 7. 常见运行提示

| 提示或现象 | 处理步骤与原因 |
| --- | --- |
| MySQL连接被拒绝 | 启动数据库窗口，核对18306监听。后端连接池需要可用实例 |
| MongoDB选择服务器超时 | 启动MongoDB，核对27017与配置地址 |
| 登录会话失效 | 后端重启或凭证到期后重新登录 |
| 构建时JAR占用 | 退出正在使用该JAR的进程，再重新构建 |
| 中文显示异常 | 用PowerShell7及项目启动脚本，脚本统一UTF-8输入输出 |
| 导入待同步 | 保留原文件，检查两库并由同一管理员重试 |
| 写入确认异常 | 先查询该业务的实际记录，结合错误代码决定重试 |
