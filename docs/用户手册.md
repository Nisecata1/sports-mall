# 运动装备商城用户手册

文档V0.6  |  软件0.2.3  |  更新日期2026-11-07

本手册对应独立Swing窗口与HTTP后端。使用者登录商城账号，项目开发者负责按需启动本机数据库与后端。当前功能及待完成范围见需求对照与进度。

## 1. 工程位置和准备

工作目录为课程“9-期末大作业_运动装备商城”下的sports-mall。该目录包含pom.xml、mvnw.cmd、src、docs和启动脚本。已使用Temurin JDK21、Maven Wrapper、MySQL8.4.13、MongoDB8.0.34。

| 程序 | 当前地址 | 架构目的 |
| --- | --- | --- |
| MySQL | 127.0.0.1:18306 / sports_mall | 保存五张关系表及数据库对象 |
| MongoDB | 127.0.0.1:27017 / sports_mall | 保存详情、评论、行为和系统日志 |
| 商城后端 | 127.0.0.1:18808 | 身份校验、业务处理和数据库访问 |
| 商城窗口 | Start-Mall.vbs启动 | 接收操作并通过HTTP显示业务结果 |
| DbGate | 连接上述数据库 | 开发者直接查看表、文档及执行查询 |

使用已有MySQL数据目录C:/develop/MySQL/data，以及课程MongoDB数据目录C:/develop/MongoDB/data。先检查相应数据库窗口是否已经运行，按需复用当前实例。

## 2. 构建和启动

在sports-mall目录打开PowerShell7，执行下列命令。

```powershell
.\mvnw.cmd package
```

Maven把Java源码编译为类，打包依赖后生成target/sports-mall-0.2.3.jar和target/sports-mall-0.2.3-desktop.jar。构建前退出运行中的商城窗口并停止商城后端，释放对应JAR。

数据库尚未启动时，在各自PowerShell窗口运行已有实例。MySQL命令如下。

```powershell
$mysqlBase = 'C:\develop\MySQL\mysql-8.4.13-winx64'
& "$mysqlBase\bin\mysqld.exe" --no-defaults --console `
  --basedir="$mysqlBase" --datadir='C:\develop\MySQL\data' `
  --port=18306 --bind-address=127.0.0.1 --mysqlx=OFF
```

课程MongoDB命令如下。

```powershell
& 'C:\develop\MongoDB\server\bin\mongod.exe' `
  --dbpath='C:\develop\MongoDB\data' `
  --bind_ip=127.0.0.1 --port=27017
```

这两个窗口保持运行，分别提供存储服务。命令指定已有数据目录与端口，业务数据由该目录中的实例继续保存。

随后在项目目录运行后端。

```powershell
.\Start-Backend.ps1
```

也可以双击Start-Backend.cmd。输入MySQL连接密码，看到后端接口就绪后保留这个窗口。后端建立连接池和共享MongoClient，负责应用的数据访问。

最后双击Start-Mall.vbs打开客户端。登录页填写商城用户名、商城密码，成功后界面显示当前账号和角色。登录凭证由后端保存并校验，客户端通过HTTP提交后续操作。

## 3. 已有业务怎样操作

| 页面 | 操作 | 结果和对应存储 |
| --- | --- | --- |
| 登录页 | 注册普通账号，再登录 | 用户和密码摘要在MySQL，登录日志在MongoDB |
| 商品浏览 | 选商品、打开详情、结束浏览 | 两库组合详情，MongoDB保存VIEW和停留时间 |
| 我的订单 | 创建订单并确认当前价格 | MySQL事务保存商品下单金额快照 |
| 我的订单 | 按当前状态及创建日期筛选 | 返回本人范围内符合条件的订单 |
| 我的订单 | 取消本人待处理订单 | 调用取消过程，订单状态转为已取消 |
| 商品评论 | 发表评分、文字及标签，读取最新评论 | MongoDB保存文档并按时间读取 |
| 数据统计 | 评论统计、热门排行、本人活动 | MongoDB聚合后返回统计范围和结果 |
| 我的账号 | 查看账号、修改电话、维护档案 | MySQL更新对应用户或档案记录 |

当前每笔订单购买一件商品，商品后续改价时历史订单金额保留。开始、结束日期均包含当天。评论评分为1至5，最新列表最多显示20条，评论统计计算全部评论。

## 4. 跟着源码完成一次档案保存

先在编辑器打开现有工程，按下表定位代码。所有Java路径以src/main/java/com/sportsmall为起点。

| 顺序 | 文件和方法 | 观察什么 |
| --- | --- | --- |
| 1 | desktop/MallDesktop.java，editProfile | 输入框内容怎样交给api.saveProfile |
| 2 | client/MallApiClient.java，saveProfile | 四个字段怎样变成PUT /api/me/profile |
| 3 | server/MallApiServer.java，profile分支 | 登录身份怎样确定，调用哪个Service |
| 4 | service/ProfileService.java，saveMine | 账号状态、长度和空字段检查 |
| 5 | dao/mysql/ProfileDao.java，save | SQL参数、用户行锁、写入及读回 |
| 6 | util/JdbcTransactions.java，execute | 一次保存的提交与失败处理 |

进入“我的账号”，观察后端终端出现GET /api/me/profile。该请求读取当前档案。随后点击“编辑我的档案”，窗口会预填已保存字段。可保留现有内容保存一次，同时观察后端出现PUT请求、维护本人档案、HTTP状态和耗时。

保存表单包含姓名、证件号码、地址和备注四个字段。姓名最多50字符，证件20，地址500，备注2000。空白字段保存为SQL NULL，备注上限为工程约定。

在DbGate新建查询并执行下面的只读SQL，观察账号主键、档案主键和关联账号编号。

```sql
SELECT u.user_id AS account_id, u.username,
       p.profile_id, p.user_id AS profile_user_id,
       p.real_name, p.address
FROM sports_mall.users AS u
LEFT JOIN sports_mall.profiles AS p ON p.user_id = u.user_id
WHERE u.username = 'mall_user01';
```

换用其他账号时修改WHERE中的用户名。users.user_id是账号主键，profiles.profile_id是档案自己的主键，profiles.user_id是关联账号的外键。唯一user_id控制每用户一份档案。首次保存会新增，后续保存按该唯一值更新已有记录。

再点击“资料与订单概览”，姓名和地址由视图关联profiles得到。这样可以同时看到界面输入、HTTP请求、后端SQL、数据库记录和再次查询的显示结果。

“删除我的档案”在确认后删除本人档案。操作前保留需要的内容，再用关联查询观察档案列变化。账号继续存在，档案为可选资料。删除已通过隔离接口检查，主库删除结果按实际操作记录。

## 5. 月度报表与数据库对象

已有月报能查询时直接进入“数据统计→我的月度订单”。填写YYYY-MM，例如2026-10。统计按创建月份筛选订单，展示当前各状态数量，已完成金额使用订单历史金额。

开发者需要核对过程时，在DbGate执行下列语句。

```sql
CALL sports_mall.sp_monthly_order_report(1, '2026-10-01');
```

Java的OrderDao通过CallableStatement调用同一过程，普通用户窗口的用户编号取自登录会话。此前已确认用户1的2026-10报表为总数1、已取消1、已完成金额0.00元，后续数据操作会改变结果。

数据库对象脚本位于src/main/resources/sql。已有主库已经安装两个视图、两个过程及两个订单触发器。新建独立环境时按schema、triggers、procedures、views及Mongo初始化顺序安装。既有商品表补单价使用单独迁移。执行脚本时先确认目标实例和现有结构。

## 6. 查看日志和处理提示

后端终端包含启动消息、请求接收和请求完成消息。例如GET /api/me/profile对应读取档案，PUT对应保存，DELETE对应删除。HTTP 200表示该接口返回成功，400表示参数或业务校验拒绝，401要求重新登录，503表示数据访问等暂未完成。

请求日志记录固定接口名称、方法、请求编号、状态和耗时。MongoDB system_logs另行保存已实现的登录业务结果，可以在DbGate或mongosh中按用户和时间查询。

窗口提示后端连接失败时，检查后端终端及18808地址。提示数据库连接问题时，检查对应数据库窗口、端口和密码。后端重启后旧会话失效，需要重新登录。写入结果未确认时先查询记录，再决定是否再次操作。
