# 答辩与验收实操

软件0.3.3，2026-11-09。先沿已经实现的功能理解输入、请求与保存，再结合交付文件讲解。

## 1. 先打开技术设计第一页和答辩第3页

前端MallDesktop收集输入，MallApiClient封装HTTP请求。后端MallApiServer解析路径并确定身份，Service处理当前权限与业务条件，DAO执行SQL或MongoDB操作。数据库返回记录后，前端更新页面。DbGate从操作者角度直接查看数据库。

源码中依次打开desktop/MallDesktop.java、client/MallApiClient.java、server/MallApiServer.java。用已有的编辑我的档案动作跟读即可。搜索editProfile、saveProfile和/api/me/profile，继续查看ProfileService.saveMine与ProfileDao.save，就能对应表单、请求、校验和profiles记录。

## 2. 展示分类、商品与两库详情

进入商品浏览，先保留全部分类观察分页，再选择一个直接分类和价格区间。前端将条件交给后端ItemSearchService，ItemSearchDao在同一快照读取总数与本页。新增查询索引帮助MySQL定位符合条件的记录。

选择一件商品查看详情。名称、价格和分类来自MySQL，说明、图片与语言来自MongoDB。后端按同一个实际item_id组合结果。讲解时可以对照E-R图中的items和集合设计中的item_details。

## 3. 展示一笔订单

使用商城账号选商品，确认金额并下单。我的订单显示新编号、金额和待处理状态。取消本人待处理订单，或者由管理员处理为完成，再查询状态和月报。

对应代码为前端的订单操作、MallApiClient、POST /api/orders、OrderService.createFor、OrderDao.create。DAO在事务中读取并锁定用户与商品，校验价格，插入订单并读回，再commit。数据库触发器检查初始规则并保护后续历史字段。

这里要说明的内容是当前单价如何成为订单里的历史金额，以及哪些修改在同一个MySQL事务里完成。月报按创建月份统计当前状态，金额来自orders.amount。

## 4. 展示评论、浏览与聚合

在商品评论页查看最新评论或保存一条自己的评论，随后打开评论统计。查看详情并结束本次浏览，再打开近7天热门和本人活动。

评论写入comments，结束浏览写入action_logs。统计调用CommentDao和ActionLogDao的聚合管道，由MongoDB计算条数、评分、浏览和去重集合。热门结果需要再查询MySQL商品名称。模拟记录使用课程演示标记，展示时说明样本性质。

## 5. 展示日志导入的状态

管理员打开系统日志，可以查看LOGIN、OPERATION与IMPORT。若重复演示已有示例文件，使用同一管理员和同一原文件。回执会复用批次，已确认导入行保持确认状态。

比较时关注该IMPORT批次的记录数与MySQL暂存行。每次成功导入请求还可以产生一条OPERATION审计，因此system_logs总量可能随操作增加。批次幂等与全部系统日志数量承担不同的观察目的。

技术设计第六节和答辩第7页对应这条链路。JDBC每50行执行一次批处理，一批共用一个SQL事务，随后Mongo按稳定_id同步，再由SQL确认。失败续跑使用测试报告里的独立实例结果说明。

## 6. 讲解测试与性能

测试报告分别记录342项JUnit、427项实库/HTTP检查和用户主库操作。选择一个并发订单或部分导入案例解释预期状态与实际结果。

性能页先说明三个对照的有序结果相同，再解释执行计划里的扫描数量和中位耗时。商品查询保留Sort，订单使用复合索引直接缩小范围，Mongo本人评论复用已有索引。21次样本是在本机热缓存环境取得。
