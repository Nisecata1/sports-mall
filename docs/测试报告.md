软件0.3.3，2026-11-09。结果依据本次构建输出、测试XML、独立HTTP检查日志、性能原始JSON和用户主库截图。

| 验证层 | 本轮结果 | 证据位置 |

| JUnit5 | 342项，失败0、错误0 | target/surefire-reports，构建日志 |

## 3. 并发检查

多个首次档案保存会收敛为同一用户的一份完整档案。两个相反的分类移动请求按数据库锁与树校验处理，结果保持无环。两个管理员争抢同一待处理订单时，一个完成状态转换，另一个收到拒绝结果，订单历史字段保持。

角色相互修改会在写事务内复核操作者，评论编辑与删除的竞态按同一作者和文档条件处理。并发相同日志导入最终复用同一文档。上述场景是指定竞态检查，测试规模以脚本中的并发任务数为准。

## 4. 故障注入与恢复结果

| 注入场景 | 观察到的状态与恢复 |
| --- | --- |
| JDBC批处理中途拒绝 | 当前整批暂存事务回滚，各执行组共同处理 |
| Mongo部分行拒绝 | SQL保留PENDING，已有Mongo行保留，重试补齐 |
| Mongo完成后SQL标记拒绝 | 回执保持待确认，重试确认已有文档 |
| 成功业务写入后的审计故障 | 业务结果保留，后端记录审计异常 |
| 演示档案第二次插入失败 | 同一SQL事务的演示用户、档案、分类等回滚 |
| 演示评论校验拒绝 | 已提交SQL及详情保留，恢复校验后重跑补齐 |
| 单份详情字段更新失败 | 既有文档保持完整，返回相应错误代码 |

故障检查在自有临时实例内安装和移除测试触发器、校验规则。数据准备工具在已有记录上比较指纹，连续重跑比较数量。

## 5. 性能与数据配额

性能用原DAO SQL进行索引前后对照，分别预热3次和采样21次，完整读取结果并逐条比较有序返回。Mongo对照复用已有本人评论索引。实测计划中的订单候选行从1000到24，商品从500到300并保留排序，Mongo文档从60040到10。具体毫秒、P95、样本和查询参数见性能报告。

课程主库MySQL六表数量分别为13、12、12、22、23、121。Mongo最近自动回读为22、42、103、152。用户已提供六表DbGate截图。本报告将主库结果、临时故障和大规模合成负载分别注明。

## 6. 用户操作记录与覆盖边界

用户已逐批提供注册、登录、联系方式、订单创建与取消、订单筛选、评论、三项统计、视图和月报的程序输出，提供档案与关系查询、管理员列表、分类树和维护截图，并确认后续商品、详情、分页、评论与管理员维护GUI通过。

0.3.1主库日志窗口和一次20条导入有截图，Mongo回读确认对应批次。重复导入和故障分支的结果来自独立自动检查。0.3.2主库演示准备有两次实际回执，0.3.3空库初始化修正由临时实例复测。

自动检查覆盖有限输入和特定竞态。多用户吞吐、P99、冷缓存、远程部署、长时间运行、磁盘耗尽和完整崩溃恢复留作后续测评。此次PPTX经过导出、包结构与渲染检查，并在本机PowerPoint16.0中只读打开、导出12页PNG，核对3个原生图表和3个原生表格。实际放映和编辑交互由现场验收记录补充。
