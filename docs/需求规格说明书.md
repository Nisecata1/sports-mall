# 运动装备商城需求规格说明书

软件0.3.3，文档V1.0，2026-11-09。验收依据为《项目011_运动装备商城.docx》V1.0，发布日期2026-10-15。

## 1. 项目目标与角色

项目面向运动装备的浏览、购买记录和互动管理，采用Java、MySQL与MongoDB实现课程规定的数据库功能。系统以桌面窗口提供操作入口，以HTTP后端组织权限、业务规则和数据访问。

普通用户可以注册、登录、维护本人联系方式和档案，浏览商品、创建和取消本人待处理订单，维护本人评论，并查看统计。管理员在这些入口之外管理用户角色与状态、分类、商品基础信息与详情、订单、评论和系统日志。

数据库操作者负责按需启动MySQL、MongoDB，配置后端连接和执行结构脚本。数据库连接密码在本地启动配置中提供。商城账号密码由注册与登录界面收集，保存为PBKDF2-SHA256加盐哈希。

## 3. 已确认的业务规则

每笔订单购买一件商品。商品单价采用正数DECIMAL(10,2)，orders.amount保存下单时的单价。用户确认报价与提交时当前价格有差异时，系统要求重新确认。订单状态依次允许从0待处理转为1已完成或2已取消，终态保持。历史归属、商品、金额与创建时间由更新触发器保护。

一个用户至多拥有一份档案，profiles.user_id具有非空外键和唯一约束。档案可以晚于账号创建，姓名、证件、地址、备注按需填写。分类根节点的parent_id可为空。分类移动需要保持无环，删除需要满足子分类和商品引用规则。

商品基础信息与扩展详情分别保存于两库。详情用MySQL实际item_id关联。评论和浏览也引用实际user_id与item_id。应用在相关业务入口检查引用及当前权限，MongoDB使用BSON Long保存这些编号。

评论评分为1至5的整数，文字最多2000字符，标签最多5个。商品页的分类筛选匹配直接所属分类，默认每页10条，页容量支持1至100。日期筛选在界面包含首尾日期，后端按日边界换算。近7天统计为查询时刻向前滚动7天。

管理员角色和账号状态由后端重新读取。普通注册产生USER角色。用户列表和评论管理使用固定显示上限，商品查询使用后端分页。日志查询显示最新200条，导入支持UTF-8 JSONL，单批最多200条且文件不超过64KiB。

## 4. 数据设计与技术要求

MySQL包含users、profiles、categories、items、orders五张核心表，以及落实JDBC日志批处理的log_import_rows暂存表。主键、外键、唯一约束与CHECK共同维护关系和数值规则。当前安装两个视图、两个存储过程和两个订单触发器。

MongoDB包含item_details、comments、action_logs、system_logs四个集合。images、tags使用数组，metadata、client_info、action_detail使用嵌套文档。评论统计、热门排行、本人活动分别使用聚合管道。

Java使用DAO模式、HikariCP、共享MongoClient、PreparedStatement、显式setAutoCommit/commit/rollback、自定义异常、SLF4J与Logback。Maven Wrapper管理构建，JDK要求17及以上，本机JDK21。源码与文档同步到Gitee和GitHub。

## 7. 需求解释与实现约定

Q-01的日志存储与JDBC批处理通过增加暂存表衔接。JDBC先提交一批日志行，MongoDB按稳定编号同步，MySQL随后确认SYNCED。该方案属于本工程对两项原文要求的实现选择，教师对方案适配性的最终验收另行记录。

商品单价扩展、每用户一份档案、每订单一件商品、桌面前后端通过HTTP分进程运行，均在需求和技术文档中明确。文档覆盖截至0.3.3的实现和已取得结果，后续修改以真实源码、脚本与验证记录更新。
